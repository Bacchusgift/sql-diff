# SQL-Diff Web 可视化增强与现代UI改造设计

## 一、设计目标

对SQL-Diff的Web界面进行双重升级：
1. **功能增强**：为CREATE TABLE语句输入提供可视化表结构预览，为比对结果提供Git风格的Diff视图
2. **UI现代化**：引入现代CSS框架和设计系统，消除原始的AI生成感，提升整体美观度和用户体验

## 二、核心功能设计

### 2.1 CREATE TABLE语句可视化预览

#### 2.1.1 布局结构

在表结构比对页和AI生成ALTER页的SQL输入区域，采用左右分栏布局：

- **左侧面板**：SQL语句编辑器（可编辑）
- **右侧面板**：表结构预览表格（只读展示）
- **分隔器**：支持拖拽调整左右面板宽度比例

#### 2.1.2 渲染触发机制

采用实时解析渲染策略：
- 用户粘贴或编辑SQL语句后，延迟500ms触发解析（防抖处理）
- 解析成功后自动更新右侧预览表格
- 解析失败时在右侧显示友好的错误提示

#### 2.1.3 表结构信息提取

从CREATE TABLE语句中解析并展示以下字段信息：

| 字段类别 | 展示内容 |
|---------|---------|
| 基础信息 | 表名（顶部突出显示） |
| 列信息 | 列名、数据类型、长度/精度、默认值、是否允许NULL |
| 约束信息 | 主键标识、唯一约束、外键关系 |
| 元数据 | 列注释（COMMENT）、字符集（如适用） |

表格展示格式：

```
表名: users

┌─────────────┬──────────┬────────┬──────────┬──────┬──────┐
│ 列名        │ 类型     │ 长度   │ 默认值   │ NULL │ 约束 │
├─────────────┼──────────┼────────┼──────────┼──────┼──────┤
│ id          │ INT      │ -      │ -        │ NO   │ PK   │
│ username    │ VARCHAR  │ 50     │ -        │ NO   │ UQ   │
│ email       │ VARCHAR  │ 100    │ -        │ YES  │ -    │
│ created_at  │ DATETIME │ -      │ NOW()    │ NO   │ -    │
└─────────────┴──────────┴────────┴──────────┴──────┴──────┘
```

#### 2.1.4 SQL解析策略

**方案选择**：复用后端已有的SQL解析能力

实现流程：
1. 前端检测到SQL输入变化
2. 通过防抖函数延迟500ms后调用后端解析接口
3. 后端利用现有parser模块解析CREATE TABLE语句
4. 返回结构化的表定义JSON数据
5. 前端根据JSON渲染预览表格

新增后端接口：`POST /api/parse-create`

请求格式：
```
{
  "sql": "CREATE TABLE users (...)"
}
```

响应格式：
```
{
  "success": true,
  "table_name": "users",
  "columns": [
    {
      "name": "id",
      "type": "INT",
      "length": null,
      "default": null,
      "nullable": false,
      "is_primary": true,
      "is_unique": false,
      "comment": ""
    },
    ...
  ]
}
```

### 2.2 Git风格Diff视图

#### 2.2.1 应用场景

提供两种Diff视图模式：

**场景一：比对前预览**
- 位置：在"开始比对"按钮下方，点击"预览差异"按钮时展开
- 作用：用户可在执行比对前，通过并排视图直观查看两个表的结构差异
- 展示方式：左右并排的表结构对比，差异列高亮标识

**场景二：比对结果展示**
- 位置：替换当前的DDL列表展示方式
- 作用：以可视化方式呈现ALTER语句将产生的变更效果
- 展示方式：树状结构 + 颜色标记

#### 2.2.2 视觉设计规范

采用GitHub风格的颜色高亮方案：

| 变更类型 | 背景色 | 边框色 | 图标 |
|---------|-------|-------|------|
| 新增字段 | #e6ffed | #28a745 | + |
| 删除字段 | #ffeef0 | #d73a49 | - |
| 修改字段 | #fff3cd | #ffc107 | ~ |
| 无变化 | #ffffff | #e1e4e8 | = |

#### 2.2.3 树状结构展示

对于复杂的表结构变更，采用可折叠的树状视图：

```
📦 users (表)
 ├─ ✅ 新增字段
 │   ├─ + phone VARCHAR(20)
 │   └─ + last_login DATETIME
 ├─ ⚠️ 修改字段
 │   ├─ ~ email: VARCHAR(100) → VARCHAR(255)
 │   └─ ~ status: TINYINT → ENUM('active','inactive')
 └─ ❌ 删除字段
     └─ - old_column INT
```

#### 2.2.4 并排对比视图

左右分栏展示源表和目标表结构：

- 左侧：源表（Source）
- 右侧：目标表（Target）
- 中间：视觉连接线，标识字段的对应关系
- 差异高亮：同名字段若属性不同，则以黄色背景标记；新增/删除字段以绿色/红色背景标记

### 2.3 交互增强

#### 2.3.1 编辑器增强

- **语法高亮**：SQL关键字高亮显示
- **行号显示**：便于定位错误
- **自动缩进**：粘贴SQL时自动格式化
- **全屏模式**：支持全屏编辑大型SQL语句

#### 2.3.2 响应式适配

- **桌面端**：左右分栏布局，最小宽度1200px
- **平板端**：上下堆叠布局，SQL编辑器在上，预览在下
- **移动端**：通过Tab切换SQL编辑和预览视图

## 三、UI现代化改造设计

### 3.1 设计系统选择

引入专业CSS框架与组件库，避免从零手写样式：

#### 3.1.1 核心框架

**Tailwind CSS**（通过CDN引入）
- 原因：现代化的原子类工具框架，灵活且美观
- 版本：v3.4+
- 引入方式：CDN链接（无需构建工具）

#### 3.1.2 UI组件库

**DaisyUI**（Tailwind CSS插件）
- 原因：基于Tailwind的组件库，提供开箱即用的现代组件
- 优势：按钮、卡片、表单、模态框等组件风格统一
- 引入方式：CDN链接

#### 3.1.3 图标系统

**Lucide Icons**
- 原因：现代、简洁的开源图标库
- 用途：替换Emoji表情图标，提升专业感
- 引入方式：CDN链接 + SVG内联

#### 3.1.4 代码编辑器

**CodeMirror 6**
- 原因：专业的代码编辑器库，支持SQL语法高亮
- 功能：行号、语法高亮、自动补全、主题切换
- 引入方式：ESM CDN（如unpkg或esm.sh）

### 3.3 页面布局重构

#### 3.3.1 导航栏改造

**当前问题**：
- 导航按钮样式朴素
- Logo缺乏视觉吸引力

**改造方案**：
- Logo区域添加图标 + 渐变色文字
- 导航按钮采用Pill胶囊样式，激活态带微妙动画
- 添加顶部进度条（页面加载时显示）
- 右侧添加主题切换按钮（明/暗模式）

#### 3.3.2 表单区域改造

**当前问题**：
- 输入框样式简单
- 缺乏视觉层次

**改造方案**：
- 表单区域采用卡片容器包裹，带阴影和圆角
- 输入框添加Focus环效果
- Label文字增加图标前缀
- 添加字符计数器（SQL输入框右下角）
- Checkbox/Radio采用现代化开关样式

#### 3.3.3 结果展示区改造

**当前问题**：
- DDL列表缺乏视觉吸引力
- AI分析结果区域单调

**改造方案**：
- DDL语句使用代码块组件，支持一键复制单条语句
- 差异摘要采用Info卡片样式，带图标和彩色边框
- AI分析结果使用手风琴折叠面板，分段展示
- 添加动画过渡效果（淡入、滑入）

#### 3.3.4 加载与反馈优化

**当前问题**：
- 加载动画简单
- Toast提示不够明显

**改造方案**：
- 加载动画使用骨架屏（Skeleton）而非全屏遮罩
- Toast提示位置调整至右上角，带滑入动画
- 添加进度指示器（AI生成时显示处理进度）
- 错误提示使用Alert组件，带关闭按钮

### 3.4 暗色模式支持

**实现策略**：
- 利用Tailwind的dark:变体实现暗色样式

### 4.2 后端接口扩展

#### 4.2.1 新增解析接口

接口路径：`POST /api/parse-create`

功能：解析CREATE TABLE语句，返回结构化表定义

处理流程：
1. 接收前端传入的SQL语句
2. 调用内部parser包的解析函数
3. 提取表名、列定义、约束信息
4. 转换为JSON格式返回
5. 错误处理：返回具体的语法错误位置和提示

#### 4.2.2 比对接口增强

接口路径：`POST /api/compare`（现有接口，需扩展返回字段）

新增返回字段：
- `structured_diff`：结构化的差异对象，包含字段级别的变更详情
- `source_structure`：源表的结构化定义
- `target_structure`：目标表的结构化定义

返回格式示例：
```
{
  "success": true,
  "has_changes": true,
  "ddls": ["ALTER TABLE users ADD COLUMN phone VARCHAR(20);"],
  "summary": "新增1个字段",
  "structured_diff": {
    "added_columns": [
      {"name": "phone", "type": "VARCHAR", "length": 20}
    ],
    "modified_columns": [],
    "dropped_columns": []
  },
  "source_structure": {...},
  "target_structure": {...}
}
```

### 4.3 兼容性保障

#### 4.3.1 浏览器支持

目标浏览器：
- Chrome/Edge 90+
- Firefox 88+
- Safari 14+

降级策略：
- 不支持的浏览器显示提示信息，建议升级
- 核心功能（表结构比对）在旧浏览器仍可用，但UI简化

#### 4.3.2 无网络环境处理

CDN资源加载失败时：
- 显示友好的错误提示
- 降级至基础CSS样式（保留style.css中的备用样式）
- 禁用依赖外部库的高级功能（如代码编辑器）

## 七、风险与缓解

### 7.1 技术风险

| 风险 | 影响 | 缓解措施 |
|-----|------|---------|
| CDN加载失败 | 用户无法正常使用 | 提供本地备用资源，或降级至基础样式 |
| SQL解析性能瓶颈 | 大型SQL语句解析缓慢 | 前端限制输入长度，后端添加超时控制 |
| 浏览器兼容性问题 | 部分用户体验降级 | 渐进式增强策略，核心功能保证可用 |

### 7.2 设计风险

| 风险 | 影响 | 缓解措施 |
|-----|------|---------|
| 过度设计导致性能下降 | 页面加载变慢 | 按需加载，优先核心功能 |
| 新UI学习成本高 | 用户不适应 | 保持操作流程一致，添加引导提示 |
| 暗色模式颜色对比度不足 | 可读性差 | 严格遵循设计规范，进行对比度测试 |
